Manual review findings

Barriers found by keyboard-only and screen reader testing that automated tools cannot detect.

critical

Subscribe control is not keyboard accessible

The newsletter 'Subscribe' control is a <div> with an onclick handler. It cannot be reached with Tab or activated with Enter/Space, and screen readers do not announce it as a button.

WCAG 2.1.1 Keyboard (Level A), 4.1.2 Name, Role, Value (Level A) · Manual test

Fix: Use a native <button type="submit"> inside a <form>.

serious

Keyboard focus is invisible

The stylesheet removes the outline from every focused element (*:focus { outline: none }). Keyboard users cannot see where they are on the page.

WCAG 2.4.7 Focus Visible (Level AA) · Manual test

Fix: Remove the global rule and add a visible :focus-visible style (e.g. 3px solid outline with offset).

serious

Form fields rely on placeholder text instead of labels

The search and email fields have no <label>. The placeholder disappears while typing and is not reliably announced by all assistive technologies.

WCAG 1.3.1 Info and Relationships (Level A), 3.3.2 Labels or Instructions (Level A) · Manual test

Fix: Add a <label for> for each field (visually hidden for the search field if needed) and autocomplete="email" on the email field.

moderate

Missing page structure: no landmarks, no H1, skipped heading levels

The page has no <header>, <nav> or <main> landmarks and no skip link. The main headline is a styled <div>, and headings jump from H4 to H5.

WCAG 1.3.1 Info and Relationships (Level A), 2.4.1 Bypass Blocks (Level A), 2.4.6 Headings and Labels (Level AA) · Manual test

Fix: Add header/nav/main landmarks, a 'Skip to main content' link, a single H1, and sequential H2/H3 headings.

moderate

Ambiguous link and button text

Links read 'here' and buttons read '+', which give no context out of context. The '+' buttons are also smaller than the 24×24 px minimum target size.

WCAG 2.4.4 Link Purpose (Level A), 2.5.8 Target Size (Level AA) · Manual test

Fix: Use descriptive text ('Read our privacy policy', 'Add to cart — Brazil Cerrado') and make targets at least 24×24 px (44×44 recommended).

minor

Generic page title

The page title is just 'Shop', which does not identify the site or page in browser tabs and screen reader announcements.

WCAG 2.4.2 Page Titled (Level A) · Manual test

Fix: Use a descriptive title such as 'Nordic Brew — Specialty Coffee Shop'.

Methodology & limitations

Automated testing with axe-core 4.14.1 in Chromium against WCAG 2.0/2.1/2.2 A and AA rules. Automated tools detect only part of all accessibility barriers; items flagged as "need manual review" and checks such as keyboard navigation order, focus visibility, screen reader announcements and content meaning require manual testing. This report is a technical assessment, not a legal certification of compliance.
